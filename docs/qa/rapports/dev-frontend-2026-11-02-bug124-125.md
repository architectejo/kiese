## BUG-124 — Affichage de `carried_debt_in` (Commissions)

- Contrat backend (rapport dev-backend) : `carried_debt_in` est un champ
  **lecture seule**, recalculé automatiquement par `ClientCommission.compute()`
  à chaque génération — jamais une valeur stockée en entrée. Il reprend la
  valeur absolue du `net_payable` négatif de la commission la plus récente du
  même client/nœud, strictement antérieure à la période courante. Déduit de
  `net_payable` **sauf** si un ajustement manuel (`manuel_adjustment`,
  DIRECTION) est en vigueur, auquel cas le report n'est pas réappliqué.
- Fichiers modifiés :
  - `frontend/src/api/services.ts` : ajout de `carried_debt_in: string` à
    l'interface `ClientCommission` (champ additif, documenté comme lecture
    seule).
  - `frontend/src/pages/dashboard/Commissions.tsx` :
    - Fiche de paie détaillée (modale ouverte au clic sur une ligne du
      tableau) : nouvelle ligne « (−) Report période précédente » insérée
      entre les retenues existantes (dette/sociale/imprimés/autre/remise) et
      le total « NET À PAYER », en rouge (même code couleur que les autres
      déductions), visible uniquement si `carried_debt_in > 0`. Info-bulle :
      « Dette de commission non réglée lors de la période précédente,
      reportée et jamais remise à zéro ». Si `manuel_adjustment` est
      renseigné sur la commission, une mention secondaire précise que le
      report n'est pas appliqué au net à payer dans ce cas (fidèle à la
      formule backend).
    - Tableau listing : petit badge rouge « Report » à côté du nom du client
      quand `carried_debt_in > 0`, avec info-bulle donnant le montant exact —
      cohérent avec le marqueur « ✎ » déjà existant pour les ajustements
      manuels.
- Pas touché : impression (`handlePrint`) et export Excel (`handleExportExcel`)
  du tableau — hors périmètre strict du ticket (affichage « listing de paie /
  fiche commission »), le listing imprimé/exporté garde ses colonnes actuelles
  (NET/ORDI, CARTE, NET/CARTE, NET À PAYER) ; le report reste visible pour
  l'utilisateur à l'écran via le badge et la fiche. À signaler si le
  coordinateur souhaite l'ajouter aussi à l'impression/export.
- Vérification manuelle recommandée pour le testeur (aucun test E2E
  Commissions existant à ce jour) :
  1. Générer une commission où `deduction_debt` dépasse `commission_gross`
     pour un client donné (`net_payable` négatif).
  2. Générer la période suivante pour le même client/nœud.
  3. Dans Commissions : vérifier le badge « Report » sur la ligne du
     tableau, puis ouvrir la fiche (clic sur la ligne) et vérifier la ligne
     « (−) Report période précédente » avec le montant attendu, juste avant
     le total NET À PAYER.
  4. Poser un ajustement manuel sur cette commission (bouton « Ajustement
     manuel », rôle DIRECTION) → vérifier l'apparition de la mention
     « non appliqué au net à payer... » sous la ligne de report dans la
     fiche.

## BUG-125 — Affichage de `average_unit_cost` (Production, écran Intrants)

- Contrat backend : `average_unit_cost` (CUMP) est un champ lecture seule sur
  `ConsumableStock`, recalculé à chaque entrée de stock (`ENTRY`), moyenne
  pondérée par quantité. Les sorties (`EXIT`) le figent comme `unit_price`
  pour valoriser la consommation réelle du Compte de Résultat (BUG-123).
- Fichiers modifiés :
  - `frontend/src/api/services.ts` : ajout de `average_unit_cost?: string`
    (optionnel, pour rester tolérant si un backend plus ancien ne le renvoie
    pas) à l'interface `ConsumableStock`.
  - `frontend/src/pages/dashboard/Production.tsx` (§3.2, tableau « Intrants
    — Stocks Consommables », cf. libellé BUG-094) : nouvelle colonne
    secondaire discrète « CUMP » entre « Unité » et « Statut » — texte
    atténué (`text-muted`), alignée à droite, info-bulle expliquant le Coût
    Unitaire Moyen Pondéré et son usage pour le Compte de Résultat. Affiche
    `—` si la valeur est absente (pas de régression visuelle). `colSpan` de la
    ligne « Aucun stock » mis à jour (4 → 5) pour la nouvelle colonne.
- Décision : pas d'extraction en sous-composant — modification limitée à
  quelques lignes dans le tableau existant du tab « Intrants », pas une
  refonte structurelle de `Production.tsx` (le seuil d'extraction de
  CLAUDE.md §4 vise les modifications importantes d'une page, pas l'ajout
  d'une colonne d'affichage).
- Vérification manuelle recommandée pour le testeur (aucun test E2E
  Production/Intrants existant à ce jour) :
  1. Effectuer une entrée de stock (achat) sur un consommable à un prix
     donné (ex. via le bouton « Approvisionner »).
  2. Dans Production → onglet Intrants : vérifier que la colonne CUMP
     affiche le coût unitaire pondéré attendu.
  3. Effectuer une seconde entrée à un prix différent → vérifier que le CUMP
     affiché se met à jour selon la moyenne pondérée.
